# 交付文档模板（README / 体验流程 / 生命周期）

三份内容一次写全：**README 是工程说明**，**体验流程是给使用者的脚本**，**生命周期是给运维/复访者的兜底**。
所有 `<...>` 占位必须替换为**刚探活过**的真实值；没验证过的数字不要写。

## 构建与启动

```powershell
# 1) 底座（已有可跳过）
java -jar <workspace>\jnf-harness\jnf-harness-app\target\jnf-harness-app.jar --server.port=8090

# 2) 插件（SDK 需先在本地仓库：mvn -N install + mvn -pl jnf-harness-types install -DskipTests）
mvn -o -B -DskipTests package
# 把 target\<plugin>.jar 复制到 <底座 jar 同级>\plugins\（启动自动装载）

# 3) 应用
mvn -o -B -DskipTests package
java -jar <app>\target\<app>.jar --server.port=<应用端口>
```

bash 等价：同样三条命令，`\` 换 `/`、`java -jar` 不变。

1. **打开应用**：`http://<host>:<应用端口>`

   - 试一下：<筛选 / 打开一条详情 / 切换标签>

     2. 「<问题 2>」→ 触发 `<tool_a>` + `<tool_b>`，回答应给出 <结论>

3. **在底座里验证同一套能力**：打开 `http://127.0.0.1:8090` → 对话框输入：
   - 「用 <tool_a> 查一下 <范围> 的数据」→ 能看到工具调用与结果
   - 注意：应用内助手与底座对话共用插件工具，数据口径一致

4. **写操作闭环**：在应用里 <手工做一次变更> → 回 AI 助手问「<刚变更的对象> 现在什么状态」→ 回答反映新状态
   - 重启应用后回到种子数据（内存数据不持久化）
```

## 三、服务生命周期模板（必给，避免「地址打不开」）

```markdown
## 服务生命周期

- **跑在哪**：<本机 / 某台服务器>，两个进程：底座 `:8090`（`java -jar jnf-harness-app.jar`）、应用 `:<端口>`（`java -jar <app>.jar`）
- **会被回收**：长驻进程在会话/沙箱结束后可能被回收，地址打不开先判断是否进程没了
- **怎么确认**：
  - `Get-NetTCPConnection -LocalPort 8090 -State Listen`，或 `Invoke-RestMethod http://127.0.0.1:8090/actuator/health`
  - 应用：`Invoke-RestMethod http://127.0.0.1:<端口>/`
- **怎么重启**：
  ```powershell
  Start-Process java -ArgumentList '-jar','<底座>.jar','--server.port=8090'
  Start-Process java -ArgumentList '-jar','<应用>.jar','--server.port=<端口>'
  ```
  重启后等 5~10s 再访问；插件随底座启动自动装载（catalog `installed=true`），无需手动 install
- **数据**：内存种子数据，重启即还原；写操作产生的数据不保留
- **模型**：底座对话依赖「设置 → 模型」渠道，未配置时 AI 会报错；换 key 后重新测试渠道
- **端口冲突**：8090/18xxx 被占用时换端口，但**应用代理里的 `harness.base-url` 与插件配置的 `baseUrl` 要同步改**
```
